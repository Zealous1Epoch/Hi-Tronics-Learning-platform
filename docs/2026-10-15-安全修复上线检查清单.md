# 安全 P0/P1 集中修复 · 上线检查清单（2026-10-15）

本轮修复内容（后端，配套 15 个回归用例，全量 106 passed）：

| 修复 | 行为变化 |
|---|---|
| SSO fail-open | 无 `SSO_SHARED_SECRET` 时不再回退 md5 兼容模式，`/sso/login` 返回 **503**；需显式 `SSO_ALLOW_INSECURE_COMPAT=true` 才恢复旧行为 |
| create_all 双轨 | `DEBUG=false` 时启动**不再自动建表**，表结构只认 alembic |
| 空密码账号 | 创建/编辑用户密码强制 ≥6 位，PUT 显式空串拒绝（省略 = 不修改） |
| admin 自降级 | 通用编辑接口不能再改自己的角色；任何路径不能消耗最后一个启用态 admin |
| DEBUG 默认值 | 默认 `false`；生产 .env 漏配时启动强校验默认生效，不合规直接启动失败 |

## 部署前（按顺序执行）

1. **alembic 先行（硬前置）**：生产库执行 `alembic upgrade head`。
   若生产表历史上由 create_all 建立、库里没有 `alembic_version` 表：先 `alembic current` + 比对实际 schema，再 `alembic stamp head` 对齐，避免 upgrade 报「表已存在」。
2. **SSO 密钥决策**：检查生产 `.env` 的 `SSO_SHARED_SECRET` 是否非空。
   - 已配置且 OA 侧已按 `HMAC-SHA256(secret, "工号:YYYY-MM-DD HH:MM:SS")` 签票 → 什么都不用做，保持开关不设或 false。
   - OA 侧尚未改造 → **临时**在 .env 加 `SSO_ALLOW_INSECURE_COMPAT=true` 过渡，并向 OA 侧立 HMAC 改造排期。该模式下票据与工号无关、任何人可伪造登录任意工号，严禁长期保留。
3. **空口令存量排查**：历史上 PUT `{"password":""}` 可能已写入空密码账号。对 `password_hash` 非空的用户逐个跑 `bcrypt.checkpw(b"", hash.encode())`，命中者立即重置强密码：
   ```python
   # 在服务器上于 server/ 目录执行（只读排查，不修改数据）
   from app.database import SessionLocal
   from app.models.user import User
   from passlib.hash import bcrypt
   db = SessionLocal()
   hits = [u.username for u in db.query(User).filter(User.password_hash.isnot(None), User.password_hash != "").all()
           if bcrypt.checkpw("", u.password_hash)]
   print("空密码账号:", hits or "无")
   ```
   （以项目实际使用的 hash 库为准，如 bcrypt 库则用 `bcrypt.checkpw(b"", ...)`。）
4. **生产 .env 合规确认**（任一不合规现在会**启动失败**——这是预期行为，启动失败好过带病服务）：
   - `DEBUG=false`（或删除该键依赖新默认值）
   - `JWT_SECRET` 为随机长字符串（非 change-me-in-production）
   - `ADMIN_PASSWORD` 强口令且非空

## 部署后冒烟

- 未配密钥时 `GET /api/.../sso/login?workcode=x&tokendate=y` → 503；已配密钥 → OA 真实免密跳转端到端成功（302 → /sso/callback?code=）
- 创建 5 位密码用户 → 422；6 位 → 201
- 管理员编辑自己：改姓名（表单携带未变更的 role）→ 200；把自己改为学员 → 400
- `logs/app.log` 复核启动日志：SSO 配置状态 WARNING 与实际模式一致；DEBUG=false 时出现「跳过 create_all」
- 监控：若上线后 `/sso/login` 出现 5xx 告警，说明生产密钥丢失/配置漂移，立即按第 2 步处置

## 运维注意

- 保持至少 **2 个启用态 admin**（本轮守卫只防清零，不防唯一 admin 忘密码）
- 回滚预案：本轮均为服务端收紧校验，还原代码重启即可；若曾临时开 `SSO_ALLOW_INSECURE_COMPAT=true`，OA 改造完成后**整行删除**而非留 false（防再次误开）
- 已知残留（如实声明，不在本轮范围）：Excel 批量导入仍接受 1-5 位密码（模板说明已加「至少 6 位」提示）；登录接口不设密码长度校验（存量短密码用户需能登录）

## 本地开发注意

- `DEBUG` 默认值已翻转为 false：本地 `.env` **必须显式 `DEBUG=true`**（现有 `server/.env` 已配置，新克隆环境从 `.env.example` 复制后注意补上），否则启动会因 JWT_SECRET/ADMIN_PASSWORD 强校验失败而退出
